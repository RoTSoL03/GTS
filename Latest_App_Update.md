## 📍 Project Context
Goat management and tracking system using **RFID tags** to identify and manage goats offline, with data sync to the cloud (planned via Supabase).

---

## ⚙️ Technical Overview
- **Language:** Kotlin  
- **Architecture:** MVVM + Room Database (Offline-first)  
- **UI Framework:** XML + Material Design  
- **RFID Hardware:** ESP32-C3 USB RFID Reader  
- **Connection:** USB-C OTG (Android USB Host)  
- **Storage:** Room (local) → Supabase (remote, planned)  
- **Auth:** Firebase (current) → Supabase Auth (target)

## ✅ Fixes & Progress

### 1. USB Permission Flow
- Introduced **UsbSetupActivity** to detect the ESP32-C3 (VID: 0x303A, PID: 0x1001).
- Requests USB permission properly via `PendingIntent`.
- Automatically launches ScanActivity after granting permission.
- Fixed `AndroidManifest.xml` intent-filter placement.
- Added recheck logic for re-entry after denial.

✅ **Result:** Reconnection after first denial now works perfectly.

---

### 2. RFID Scanning & Feedback
- Successfully reads RFID data via USB serial.
- Added **beep sound** and **confirmation dialog** for tag detection.
- Shows “Existing Tag” → open record or “New Tag” → register goat.
- Boosted beep volume using `MediaPlayer`.

✅ **Result:** Smooth scan flow with visual and audio confirmation.

---

### 3. Initial Permission Denial Fix
- First prompt sometimes shows “Permission Denied,” but reconnects properly afterward.
- Implemented **Option A**: a friendly setup screen for first-time permission granting.

✅ **Result:** Consistent connection flow.

---

## 🐞 Current Bug
### Symptom:
After scanning RFID, **multiple toasts** appear (“Invalid call”, duplicates).

### Likely Causes:
- Serial listener triggers multiple times.
- Duplicate permission or connection reinitializations.
- Fragmented read data.

### Planned Fix:
- Debounce mechanism to prevent multiple reads.
- Unregister listeners on activity exit.
- Replace repeated toasts with cleaner feedback (dialogs or logs).
